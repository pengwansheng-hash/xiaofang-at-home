# UI 规格说明

## 1. 设计目标

- 适老化：大字、大按钮、高对比、浅层级、少动画
- 温暖可信：避免医疗恐惧风，不制造被监视感
- 低噪音：老人端尽量 1-2 步完成操作，子女端优先展示结论再展示细节
- 安卓原生落地时，优先保持 v0 原型的页面信息架构、卡片比例、留白和配色气质

## 2. 视觉原则

- 老人端以清晰、稳定、温和为主
- 子女端以结果驾驶舱为主，不展示信息洪流
- 不使用复杂图表，不堆叠技术术语
- 高风险内容必须显式确认，不用模糊话术

## 3. 老人端页面规格

### 3.1 首页
- 模块：问候语、今日提醒卡片、今日完成进度、语音主按钮
- 首要动作：开始说话、查看今日待办
- 今日提醒卡片：需从当前提醒计划中动态取值，优先展示最近一条待处理提醒

### 3.2 待办录入页
- 支持事项：吃药、喝水、吃饭、运动、休息、复诊
- 字段：事项类型、时间、频率、是否需要确认
- 交互：字段少、按钮大、默认值明确
- 若频率为“每周”，需出现星期选择区，至少支持周一到周日的多选

### 3.3 今日待办页
- 模块：即将执行、未完成、已完成
- 操作：确认完成、稍后提醒、补录完成
- 列表信息层级：主行展示时间 + 事项；副行展示规则与提醒方式，例如“周一、周三、周五 · 语音播报 / 闹钟铃声”
- 状态表达：当前待处理显示更强状态色；后续待处理显示弱状态色；单次提醒过期后需给出明确说明，不再像可重复提醒一样展示

### 3.4 对话页
- 模块：语音按钮、文字输入框、发送按钮、语音弹框、AI 回复气泡
- 要求：弱化复杂操作，突出听和说
- 语音按钮：底部输入条左侧显示麦克风图标，单击后弹出语音输入框，不再通过切换模式把中间输入区替换成“按住说话”
- 语音弹框：必须包含当前状态、实时声纹或音量条、最近识别文本、大号“按住说话”按钮和关闭入口
- 录音交互：在弹框内按下开始录音、松开结束录音；录音中按钮、状态文案和声纹条都要明显变化
- 转写结果：识别成功后，最近识别文本要在弹框内可见，同时消息区马上出现老人消息气泡
- 权限处理：首次使用语音按钮时请求麦克风权限；拒绝后给出清晰说明，不强行跳复杂系统页
- 触达要求：陪伴页、绑定页、资料页的主要按钮高度不低于 56dp；次要筛选项不低于 48dp
- 说明前置：绑定码、语音录制、权限提示优先用短句直接说明“下一步该做什么”

### 3.5 提醒确认页
- 主按钮：我已完成、稍后提醒、需要帮忙
- 场景：提醒触发后必须快速完成动作
- 点“需要帮忙”后进入求助确认页，不直接跳失控的复杂列表

### 3.6 偏好设置页
- 字段：称呼、常聊话题、禁忌词、提醒方式
- 首版输入方式：称呼单行输入，常聊话题与禁忌词使用大输入框
- 保存策略：本地即时持久化，后续再接家庭同步
- 交互要求：保存按钮大、反馈明确，避免隐藏式自动保存造成困惑

### 3.7 一键联系页
- 动作：联系家属、联系紧急联系人
- 状态：联系中、联系成功、联系失败三态明确

### 3.8 服务连接设置
- 位置：老人端绑定页内的服务连接卡，和绑定码信息同屏展示。
- 输入：服务地址、老人 ID。
- 默认值：服务地址默认示例为 `http://10.0.2.2:3301`，用于模拟器直连。
- 提示文案：必须明确区分模拟器与真机，真机应填写电脑局域网 IP 的 `3301` 端口，`3201` 仅供子女端网页前端使用。
- 反馈：保存并测试后，失败态要直接显示正在检查的完整 `/api/ai/runtime` 地址，避免只说“连接失败”。

## 4. 子女端页面规格

### 4.1 绑定页
- 方式：输入绑定码或扫码
- 成功后进入今日状态页
- 首版技术落地：移动 H5 单栏布局，优先保证微信内浏览器与常见 Android 浏览器可读可点
- 首版成功态：绑定成功后本地保留当前家庭上下文，今日状态页顶部明确显示“已连接谁”
- 成功态补充：绑定页本身要展示家庭上下文卡，至少包括老人姓名、当前绑定码、绑定时间、绑定方式，以及去今日状态/提醒/资料页的快捷入口
- 扫码占位：首版按钮点击后也要给出明确反馈，例如自动填入示例码、标记“扫码导入”方式，并同时提示“待服务端校验”

### 4.2 今日状态页
- 首屏内容：今日结论、风险等级、是否需要介入
- 次级内容：完成项、待办剩余、最近记忆片段
- 页面骨架：顶部结论摘要 + 中部状态卡片流 + 底部轻量导航，不使用复杂浮层和图表
- 若尚未绑定，首屏先提示“这是示例骨架”，并给出返回绑定页的明确入口
- 与提醒设置联动：提醒页新增或修改后，今日状态页的数量卡片、首要提醒说明和“今晚最值得做的动作”需立即更新
- 绑定联动：绑定成功后，今日状态页首屏增加一张家庭上下文卡，明确显示“当前正在看谁、什么时候绑上的、是手输还是扫码、现在最自然的下一步是什么”
- 异常联动：今日状态页需直接显示当前待介入异常数量；如果已有异常卡，首屏摘要和风险提示优先反映异常，而不是只看提醒待同步状态

### 4.3 提醒设置页
- 功能：查看每日提醒、新增提醒、编辑时间/频率/优先级/确认要求
- 首版交互：页面内展开提醒编辑卡，支持新增和修改标题、时间、频率、提醒方式，保存后立即更新列表
- 删除入口：每张提醒卡片保留明确删除按钮，删除后列表和今日状态页同步刷新
- 状态保留：未接服务端前，先在浏览器本地保存提醒计划，避免每次刷新都回到初始 mock

### 4.4 老人信息页
- 内容：基础信息、偏好、常聊话题、禁忌词、重要联系人、作息
- 首版交互：页面内展开本地编辑卡，支持修改称呼风格、常聊话题、禁忌词和作息描述，保存后立即反映到资料页
- 状态保留：未接服务端前，先在浏览器本地保存资料修改结果，避免刷新后回到初始 mock
- 联系人编辑：资料页至少支持本地新增 1 位联系人、修改关系与手机号，并保留直拨入口

### 4.5 异常页
- 内容：异常摘要、建议动作、一键联系
- 联动规则：首版异常卡由绑定状态、本地提醒计划和待同步状态共同决定；提醒页刚改过内容或存在待确认提醒时，这里要立即出现对应异常卡
- 首版动作：主按钮优先给出“去绑定 / 去提醒页 / 现在联系”这类明确动作；次按钮“稍后处理”只在当前浏览器本地压住该异常，不影响后续真实同步
- 空状态：如果当前没有需要介入的异常，明确显示“今天先不用急”，避免子女端像告警后台一样持续制造焦虑

### 4.6 鼓励页
- 内容：留言、点赞、红包占位

### 4.7 子女端壳层规则
- 默认使用移动端单栏壳层，页面最大宽度控制在手机阅读舒适区间
- 顶部区域优先展示“今天要不要介入”的结论，不把配置项堆到首屏
- 底部导航首版保留“今日”“提醒”“异常”“资料”4 个入口，鼓励页先作为次级入口存在

## 2026-04-15 对话页输入栏补充
- 底部输入区固定为三段式布局：左侧语音按钮、中间文字输入框、右侧绿色发送按钮。

## 2026-04-15 陪伴页回复语气补充
- 陪伴页的输入布局保持现有微信式结构不变，但回复内容需要进一步体现“记得我、懂我、接得住我”的感觉。
- 回复生成时需要优先使用本地语义记忆、提醒摘要和情绪提示，避免只输出机械式的“我听到了”“我明白了”。
- 服务不可用时，页内仍需走本地记忆兜底，保证老人看到的是有上下文的中文回复，而不是空白等待或泛化模板。
- 当老人刚在这一轮提供了子女、居住或经历信息时，回复本轮不得继续追问另一类画像信息，先回应这句话本身。
- 当老人明显反感或让小芳别再问时，回复要先道歉并立刻收口，不再继续盘问。

## 2026-04-15 陪伴智能 V1 交互补充
- 陪伴页状态文案需要支持主动关怀提示，例如“好几天没聊天了，我在这儿，想聊的时候叫我”。
- 回复区继续保持当前输入栏布局，不新增复杂控件；本轮只补充文案与状态语气。
- 当系统判断情绪偏低或记忆命中时，回复语气要更稳、更慢、更接住情绪。
- 当系统命中最近记忆时，状态文案或回复中可以轻量提到“我记得您刚才说过的事”。
## 2026-04-15 轻量画像补充约束
- 回复内容可以自然补充画像信息，但陪伴优先级高于收集信息，不能让老人感到被审问。
- 优先补充顺序仍为：基本情况、子女情况、儿孙情况、人生经历，但同一轮只允许补一个点，而且必须与当前话题相关。
- 如果老人当前这一轮已经回答了画像信息，本轮不再追问同类或下一类画像问题。
- 如果老人表达抗拒、质疑目的或要求停止，后续至少一轮不再做画像追问，先换成轻松陪聊或当前情绪安抚。

- 家人与资料页继续保持“称呼 -> 沟通风格 -> 常用联系人 -> 保存”的主结构，但删除“常聊话题”输入区，避免资料页给人过度盘问信息的感觉。

- 设置页在“服务连接”卡片下方新增“多层记忆”卡片，按时间倒序展示本地长期记忆，每条卡片至少显示记忆类型、压缩摘要和删除图标。
- 设置页的记忆删除操作要足够明确：点击删除后立即从列表中消失，并以轻提示说明已删除。
- 设置页新增“位置采集”卡片，包含小时采集开关、当前状态文案和权限说明；打开时强调“每小时记录一次当前位置，用于后续活动轨迹”，关闭时强调“停止后续采集”。
- 定位权限未授权时，打开位置采集开关需要先触发系统权限申请，不直接静默失败。

## 2026-04-18 陪伴页回复链路与多层记忆展示补充
- 陪伴页回复策略分层：
  - 极短确认和收尾消息可直接本地返回。
  - 普通闲聊、天气、日常状态、轻任务询问优先尝试服务端 live 回复。
  - 模型失败时页内仍即时显示 fallback，但 fallback 语气必须像普通熟人接话，不得突出“记忆提示词”痕迹。
- 陪伴页的记忆引用规则：
  - 同一条回复最多显式引用 1 条高相关记忆。
  - 天气、寒暄、问路式短问题默认不引用情绪/家庭记忆。
  - 只有用户当前话题与记忆明确相关，才可自然提一句，不得把旧记忆硬接回来。
- 设置页“多层记忆”展示改为分组结构：
  - 长期画像：居住情况、家庭结构、长期偏好、稳定作息、重要经历、长期健康基线。
  - 交流偏好：喜欢的话题、尽量避免的话题、称呼偏好。
  - 近期状态：最近几天内仍有参考价值的身体状态或情绪状态。
- 每条记忆卡片除类型名外，还应显示：
  - 规范化摘要，而不是原始噪音句子。
  - 证据次数或重复命中次数。
  - 最近确认时间或最近更新提示。
- 低价值碎片（如天气评价、问句、一次性寒暄）不进入多层记忆列表，因此设置页默认不展示这类内容。
