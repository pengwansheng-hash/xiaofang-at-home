# 线框说明

## 1. 老人端

### 首页
- 顶部：问候 + 老人称呼
- 中部：今日待办进度卡
- 主体：最近一条提醒卡
- 底部主操作：大按钮“说句话”
- 次级入口：查看今日待办、一键联系

### 待办录入页
- 顶部：事项类型选择
- 中部：时间、频率、是否确认
- 底部：保存按钮

### 今日待办页
- 分区：待执行 / 已完成
- 每张卡片动作：完成、稍后提醒、需要帮忙

### 对话页
- 顶部：当前状态
- 中部：对话气泡和字幕
- 底部：长按语音按钮
- 语音按钮上方：短句说明“按住说话，松开结束”
- 语音按钮下方：录音状态文案
- 结果区：最近一次录音保存结果
- 结果区操作：回放最近录音 / 停止回放
- 转写区操作：语音转提醒草稿 / 结束语音转写
- 草稿卡片：展示转写文本、识别出的提醒时间、频率、事项，以及“确认保存”“重新整理”动作

### 提醒确认页
- 中央信息：当前提醒内容
- 规则区：当为每周提醒时，展示具体星期几
- 底部三按钮：我已完成 / 稍后提醒 / 需要帮忙

### 偏好设置页
- 列表项：称呼、喜欢话题、不喜欢的提醒方式、禁忌词
- 输入形式：称呼单行输入框，常聊话题 / 禁忌词多行输入框
- 底部动作：保存修改
- 次级入口：绑定子女端按钮

### 一键联系页
- 大按钮：联系家属
- 次按钮：联系紧急联系人

### 绑定码展示页
- 顶部：返回 + 标题“绑定子女端”
- 中部：操作提示卡、6 位绑定码、大号可视化码块、最后更新时间
- 底部动作：复制绑定码、换一个新的绑定码
- 动作尺寸：主按钮高度不低于 56dp，避免误触

### 服务连接设置卡
- 位置：绑定码信息下方或同屏次卡区，和绑定码共享同一个绑定页。
- 输入项：服务地址、老人 ID。
- 默认值：服务地址默认填 `http://10.0.2.2:3301`，便于模拟器直连。
- 说明文案：真机请填电脑局域网 IP 的 `3301` 端口，`3201` 仅用于子女端网页前端，不可当作 care-service 地址。
- 反馈：点击保存后，卡片下方直接展示连接状态和正在检查的完整 `/api/ai/runtime` 地址。

## 2. 子女端

### 绑定页
- 输入框：绑定码
- 按钮：绑定 / 扫码
- 首版壳层：顶部标题 + 说明文案 + 输入卡片 + 主按钮，适配微信内打开
- 成功态：显示“已绑定成功”提示，并保留一个清除当前绑定占位入口
- 成功态补充：在提示下方展示家庭上下文卡，包含老人姓名、绑定码、绑定时间、绑定方式和去今日/提醒/资料页的快捷按钮
- 扫码占位：扫码按钮点击后，页面要出现“已带回示例绑定码、待服务端校验”的反馈，不做静默按钮

### 今日状态页
- 顶部：今日结论和风险等级
- 中部：完成情况、待办剩余
- 底部：异常入口、鼓励入口
- 底部导航：今日 / 提醒 / 异常 / 资料
- 未绑定时：顶部先展示“还没连上老人端”的提示卡，并提供返回绑定页按钮
- 联动规则：提醒计划变动后，首屏的数量卡片与“今天最该盯住哪条提醒”要跟着刷新
- 绑定联动：已绑定时，在数量卡片前插入一张“当前家庭上下文”卡，展示老人姓名、绑定时间、绑定方式和下一步入口
- 异常联动：数量卡片中增加“待介入”数量；如果已有异常，首屏摘要优先提示“先去异常页看哪一条”

### 提醒设置页
- 列表：每日提醒计划
- 浮动动作：新增提醒
- 编辑区：点击新增或编辑后，在列表上方展开单栏编辑卡，包含标题、时间、频率、提醒方式和保存按钮
- 列表动作：每张提醒卡片保留“修改 / 删除”双操作

### 老人信息页
- 分组：基础信息、偏好、重要联系人、作息
- 编辑区：页面上方展开单栏编辑卡，至少包含称呼风格、常聊话题、禁忌词、作息描述和保存按钮
- 状态规则：保存后资料卡片立即刷新，刷新浏览器后仍保留当前编辑结果
- 联系人编辑区：在重要联系人模块前提供本地编辑卡，支持姓名、关系、手机号录入与保存

### 异常页
- 顶部：异常等级
- 中部：原因摘要与建议动作
- 底部：联系按钮
- 异常来源：未绑定提示、待同步提醒、待确认提醒
- 每张卡片动作：主动作直接去处理（绑定 / 去提醒页 / 现在联系），次动作“稍后处理”仅本地压住
- 空状态：当没有异常卡时，显示“今天先不用急”的说明卡

### 鼓励页
- 输入区：留言
- 操作区：点赞、红包占位

## 3. 当前线框结论

- 老人端优先级最高的页面链路是：首页 -> 提醒确认页 -> 今日待办页
- 子女端优先级最高的页面链路是：绑定页 -> 今日状态页 -> 提醒设置页 -> 异常页
- 子女端首版先搭移动 H5 壳层与 4 个主页面，再逐步补绑定成功流和提醒编辑细节
- 下一步如果进入高保真设计，应先把这两条主链路补成 Figma 页面流

## 2026-04-15 对话页线框补充
- 对话页底部输入区改为微信式三段布局：左侧语音按钮、中间文本输入区、右侧发送按钮。
- 点击左侧语音按钮后，页面中央弹出语音输入框；底部文字输入区保持不变，不再切成整块语音模式。
- 语音输入框结构：标题/状态 -> 实时声纹或音量条 -> 最近识别文本 -> 大号“按住说话”按钮 -> 关闭按钮。
- 语音采集中，弹框内要直接展示实时声纹、当前状态和松开发送提示，避免老人看不出系统已经开始听。
- 语音发送成功后，对话流应自动滚到最新消息，避免老人看不到刚发出去的内容。

## 2026-04-15 陪伴回复收口线框补充
- 当老人表达“别问了”“你问这些干什么”等抗拒信息时，对话流中的下一条小芳回复应先道歉收口，再切回轻松话题或当前情绪回应。
- 当老人刚说出“孩子在成都/上海”“我一个人住”等资料时，下一条回复优先承接这句话本身，不再立刻跳到新的画像问题。

- 家人与资料页线框：删除顶部提示语“先把称呼、风格和联系人整理好”，保留资料表单、联系人列表和保存操作。

- 设置页线框：顶部返回 + 标题；正文为服务地址输入、老人 ID 输入、保存按钮、连接状态提示。

## 2026-04-18 陪伴页线框稳定性补充
- 陪伴页顶部线框：返回按钮、老人字标、标题、喇叭开关固定一行；标题下方不再显示实时状态副标题。
- 聊天发送后的“正在想一想”“服务端暂时不可用”等过程提示不再占用顶部区域，页面继续保持聊天流为主。
- 喇叭开关在任何聊天状态下都固定显示在右上角，不参与标题区换行。

## 2026-04-18 家人与资料页 / 设置页线框补充（二）
- 家人与资料页线框：删除“常聊话题”块，页面顺序调整为“称呼 -> 沟通风格 -> 联系人列表 -> 新增联系人 -> 尽量避免的话题 -> 查看绑定码 -> 保存资料”。
- 设置页线框：顶部返回 + 标题；正文按“服务连接卡 -> 位置采集卡 -> 多层记忆列表”纵向排列。
- 位置采集卡线框：标题、说明文案、小时采集开关、当前状态文本；不增加地图预览。
- 多层记忆列表线框：每行一条记忆卡，左侧为类型与摘要，右侧为删除图标；列表为空时显示“还没有保存的长期记忆”空状态。

## 2026-04-18 多层记忆线框重构
- 设置页“多层记忆”区线框改为三级结构：分组标题 -> 分组说明 -> 记忆卡片列表。
- 分组顺序固定为“长期画像 -> 交流偏好 -> 近期状态”，避免所有记忆混在同一串时间流里。
- 记忆卡片线框：
  - 第一行：类型 badge + 证据次数 + 删除图标。
  - 第二行：规范化摘要主文案。
  - 第三行：最近确认时间或“近期状态，稍后会自动淡出”的辅助文案。
- 空状态线框改为按分组分别展示：
  - 长期画像为空时提示“还没有形成稳定画像”。
  - 交流偏好为空时提示“还没有记录到明确偏好或避讳”。
  - 近期状态为空时提示“最近没有需要挂住的短期状态”。
- 陪伴页回复链路线框补充：
  - 不在页面上直接显示“走了哪条回复路径”，但聊天流需保证普通聊天返回的话术自然，不出现明显模板断层。
  - fallback 回复与 live 回复都复用同一消息气泡样式，不额外暴露技术状态。

  - 第二层：两张快捷入口卡，左“联系家人”，右“语音陪伴”。

  - 顶部：摘要标题“今天还有 X 件重要事”+ 一句轻提示。
  - 主体：左时间线、右提醒卡片。
  - 底部：一张陪伴提示卡。
- 陪伴页：
  - 顶部：返回 + 标题区 + 喇叭开关。
  - 中部：聊天气泡流。

  - 第一块：称呼卡。
  - 第二块：沟通风格双按钮。
  - 第三块：联系人列表卡片。
